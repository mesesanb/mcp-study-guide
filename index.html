Lesson 1

What MCP is

Model Context Protocol (MCP) is a standard for connecting AI applications to external tools and data. It helps you connect Claude or other models to services without writing one-off wrappers over and over.

MCP gives you a shared language for tools, resources, and prompts so the AI can work with a system in a predictable way.

Lesson 2

MCP client and server

The host is your application. The client sits inside it and talks to the server. The server exposes tools, resources, and prompts. That separation keeps the app logic clean and the external integrations reusable.

flowchart LR
A[Your app] --> C[MCP client]
C --> S[MCP server]
S --> X[External tool or data source]
Lesson 3

Project setup

In the course project, the app creates a document chat where Claude can read and edit document content using tools. The project includes a server with a document store, a client wrapper, and a simple chat loop.

The key idea is that the app does not manually hardcode every tool call. Instead, it discovers tools through MCP and then hands them to Claude when needed.

Lesson 4

Tools

Tools are functions the model can call when it decides it needs to do something. For example, reading a document or editing a file.

@mcp.tool()
def read_document(doc_id: str):
    return docs[doc_id]

Good tool descriptions matter, because the model uses them to decide whether a tool is relevant.

Lesson 5

Inspector

The MCP Inspector is a debugging tool that lets you test a server without building a full client first. It is the easiest way to verify that tools, resources, and prompts are exposed correctly.

mcp dev mcp_server.py
Lesson 6

Client

The client connects to the server, initializes the session, lists tools, and calls tools when the model asks for them.

await session.initialize()
result = await session.list_tools()
Lesson 7

Resources

Resources are read-only data exposed as URIs, such as a list of available docs or a specific document by id.

@mcp.resource("docs://documents/{doc_id}")
def fetch_doc(doc_id: str):
    return docs[doc_id]

Resources usually power autocomplete or prompt context injection, rather than model-controlled actions.

Lesson 8

Reading resources

The app reads a resource itself and injects the data into the conversation. This is useful for things like showing a list of docs or adding file contents to a prompt before the model answers.

Lesson 9

Prompts

Prompts are reusable instruction templates that the user can trigger. They are useful for common workflows like “format this document” or “summarize this thread.”

@mcp.prompt(name="format")
def format_document(doc_id: str):
    return [UserMessage(f"Format {doc_id} as Markdown.")]
Lesson 10

Using prompts in the client

The client can list available prompts and then fetch a rendered prompt with arguments. The server can return a batch of prompt messages, which are then passed into the conversation.

Lesson 11

Review

The easiest way to remember MCP is this:

  • Tools = model decides to act
  • Resources = app decides to fetch data
  • Prompts = user triggers a workflow
